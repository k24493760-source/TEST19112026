# ПОЛИТИКА ОТВЕТА И ДОКАЗАТЕЛЬНОСТИ

- Каждое содержательное утверждение сопровождается ссылкой на конкретный фрагмент утверждённого источника.
- Ответ визуально разделяет: норму права; официальное разъяснение; юридическую интерпретацию; учебно-методическое объяснение.
- При отсутствии достаточного основания агент отвечает «основание не найдено», перечисляет просмотренные источники и создаёт задачу эксперту.
- При конфликте редакций агент показывает противоречие и НЕ выбирает юридическую позицию самостоятельно.
- Уверенность модели не заменяет качество источника: высокий retrieval-score не разрешает ответ по неутверждённому материалу.
- Ссылки и цитаты проходят автопроверку существования document_id, версии, страницы/раздела и соответствия фрагменту.

# МЕТОДИКА ОБУЧЕНИЯ И ОЦЕНКИ

- Банк вопросов версионируется: компетенция, сложность, правильный ответ, обоснование, источники, владелец.
- Закрытые вопросы: детерминированный результат; порядок вариантов может меняться, ключ — нет.
- Свободный ответ: рубрика (обязательные элементы, допустимые формулировки, критические ошибки, ссылки), сохраняется rationale.
- Порог утверждается владельцем программы для каждой версии и не меняется задним числом.
- Апелляция: пользователь видит основание оценки → передаёт куратору → решение пополняет эталонный набор после утверждения.
- Свидетельство: агент формирует отчёт о прохождении; официальный документ выдаёт только уполномоченная организация.

# КОНВЕЙЕР ДОКУМЕНТА (реализуй как сервис pipeline.py)

1. intake: проверка расширения, размера, пустого файла; SHA256; отсечение точных дублей.
2. version + approval: создание logical_document, version, representation; запись в expert_review.
3. parse: PDF (pdfplumber), DOCX (python-docx), HTML (BeautifulSoup), TXT → source_span + normalized_block.
4. links/assets: реестр ссылок и изображений; необязательные ошибки не валят процесс, попадают в processing_issue.
5. gate: полнота (есть span, нет error-issue, версия approved).
6. chunk: chunkset + chunk (size=600, overlap=100).
7. publish: chunkset → live; published_release; rebuild TF-IDF + embeddings.
8. journal: upload_job со stage на каждом шаге; audit_event.

# RAG (гибридный поиск)

- TF-IDF (sklearn) + dense-эмбеддинги (sentence-transformers).
- score = 0.4 × tfidf_norm + 0.6 × cosine(emb).
- Жёсткий фильтр: только чанки из документов со status=approved и chunkset.status in (approved, live).
- Модель конфигурируема через contracts/model_config.yaml:
    embedding_model: <name>
    embedding_dim: <int>
- Дефолт: intfloat/multilingual-e5-small (384).
- Проверка: при старте сверять фактическую размерность модели с embedding_dim в конфиге; при расхождении — падать с понятной ошибкой.
